# Repository Guidelines

## Project Structure & Module Organization
- `src/routes`: SvelteKit routes, endpoints, and pages.
- `src/lib`: Shared UI/components (`src/lib/components`) and utilities.
- `src/lib/server`: Server-only code (auth, db, hooks).
- `static`: Public assets served as-is.
- `drizzle`: SQL migrations and metadata generated by Drizzle.
- `data`: SQLite files (e.g., `data/dev.db`). Do not commit DB files.

## Build, Test, and Development Commands
- `npm run dev`: Start the SvelteKit dev server with HMR.
- `npm run build`: Production build.
- `npm run preview`: Preview the production build locally.
- `npm run lint` / `npm run format`: ESLint and Prettier.
- `npm run db:generate`: `drizzle-kit generate` from `src/lib/server/db/schema.js`.
- `npm run db:migrate`: Apply migrations to the SQLite DB.
- `npm run db:studio` (optional): Open Drizzle Studio.

Example env for local SQLite: `DATABASE_URL="file:./data/dev.db"`. Use `pnpm run ...` if you prefer pnpm.

## Coding Style & Naming Conventions
- TypeScript, 2-space indent, Prettier-ordered imports.
- Svelte components: PascalCase (e.g., `Button.svelte`).
- Files in `src/routes`: lowercase, dash-separated (`/auth/sign-in/+page.svelte`).
- Server modules and actions in `src/lib/server`: kebab- or snake-case filenames; named exports.
- Keep server-only code out of client bundles (place under `src/lib/server`).

## Testing Guidelines
- Unit tests: Vitest recommended; name files `*.test.ts` near sources.
- Component tests: `*.test.ts` alongside Svelte components.
- Run tests: `npm run test` (configure Vitest in `package.json` when added).

## Commit & Pull Request Guidelines
- Use Conventional Commits: `feat:`, `fix:`, `chore:`, `refactor:`, `docs:`.
- Scope examples: `feat(auth): add session refresh`, `fix(db): nullable email`.
- PRs include: purpose, linked issues, screenshots for UI, and migration notes.
- Keep PRs focused; update docs and `.env.example` when config changes.

## Security & Configuration Tips
- `.env` (not committed): `AUTH_SECRET`, `DATABASE_URL`, provider keys.
- Add `.env.example` with placeholders. Rotate secrets on exposure.
- Better Auth lives in `src/lib/server/auth` and wires into `hooks.server.ts`.
- SQLite lives under `data/`; back up before running destructive migrations.
